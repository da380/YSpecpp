Examples

Traveltime kernels

The yspec-kernels program computes adjoint kernels for cross-correlation traveltimes measured on one source's seismogram at one receiver.

{{REVISION_NOTICE}}

Build and run the bounded input

The standard CMake option defaults to YSPEC_WITH_NETCDF=ON; install the NetCDF-C development library before configuring, or set the option OFF for sections/maps-only builds. Configure three programs and build the kernel executable with a two-job cap. From the repository root:

cmake -S . -B build/kernels -DCMAKE_CXX_COMPILER=g++-13 \
  -DCMAKE_BUILD_TYPE=Release -DYSPEC_BUILD_TESTS=OFF
cmake --build build/kernels --target yspec-kernels --parallel 2
mkdir -p build/kernel-small
cp docs/site/examples/kernels-small.json build/kernel-small/input.json
cp examples/prem.200 build/kernel-small/prem.200
OMP_NUM_THREADS=2 build/kernels/bin/yspec-kernels build/kernel-small/input.json
ls build/kernel-small/kernel-small.*

The exact small input fixture requests relative velocity kernels, one T-component traveltime measurement over 300–600 s, sampled path sections and maps. The input path and model path resolve relative to the JSON file. Its short degree, frequency and record ranges keep this a documentation example rather than an accuracy benchmark.

The program writes radial kernels, per-measurement seismogram/window/adjoint-source data and, when requested, sections and maps. Volume output is opt-in. The fixture keeps the grid small; in a measured run it completed in 2.60 s through the source-built Python CLI and in 3.10 s through the C++ executable, with two OpenMP threads.

Input limits and choices

The strict JSON parser accepts exactly one source, one receiver and at least one measurement. Names are optional; unnamed measurements are numbered in input order, while supplied names must be unique and may not contain a slash. Each measurement selects component Z, N, E, R or T and a traveltime object with window_s: [start, end] and optional taper_s. The window must lie within the time series and have positive length; the taper is between zero and half the window. Unknown members are errors. The ordinary seismogram JSON accepts multiple sources and receiver groups, so do not assume its full schema applies here.

Kernel options include parameterizations love, moduli, velocities (default) and anisotropic; scaling absolute (default) or relative; and an optional quadrature mesh. Optional sections default to 15° margin, 15° half-width, 0.2° spacing and 25 km radial spacing. Maps require depths in km and default to 10° margin, 15° half-width and 0.5° spacing. A volume request defaults to degree 64 and maximum radial element length 100 km; its setting overrides the spherical degree and maximum element length used for the NetCDF grid. All lengths ending in _km are kilometres, frequencies in the shared input are mHz, and time fields ending in _s are seconds. See the fixture and the input reference.

Output and NetCDF boundary

Radial parameter kernels are written to <prefix>.kernels; each measurement also receives its measurement record and any requested sampled outputs. With multiple measurements, their names are inserted after the prefix before each suffix. Sections and maps are text outputs and work without NetCDF. The YSPEC_WITH_NETCDF CMake option defaults to ON and requires NetCDF-C during configuration; use -DYSPEC_WITH_NETCDF=OFF for a sections/maps-only build. Writing the through-earth volume requires the enabled option. The separate volume fixture demonstrates the optional request:

cp docs/site/examples/kernels-volume-small.json build/kernel-small/volume.json
OMP_NUM_THREADS=2 build/kernels/bin/yspec-kernels build/kernel-small/volume.json

The Python package build explicitly disables NetCDF and cannot write this file. Its plotting extra can read NetCDF files produced by the C++ program. A sampled section/map run does not require the volume option. For plots and file interpretation, see plotting and model and output formats.

Interpretation boundary

Radial kernels include density sensitivity, with moduli held fixed and the resulting equilibrium-gravity change included. The sampled 3D sections, maps and volume contain elastic-parameter and inverse-Q kernels at fixed density; they do not contain a 3D density kernel. In the bounded velocity-set fixture, the radial table has rho, vp, vs, qkappa and qmu columns, while sampled outputs contain vp, vs, qkappa and qmu. Other parameter sets change these names. The radial P_X source-point term has no representation on the sampled 3D grids: the 3D files contain sampled continuous fields and omit this concentrated contribution, so they do not by themselves represent the full sensitivity including the source-point term. See the sampled-kernel API contract and derivation. Kernel parameterization, scaling, mesh, selected component, window and model all affect the output. Existing tests include finite-difference checks and volume-file checks, but they do not establish convergence or accuracy for arbitrary models and input settings. For C++ library-level control, see the library guide.

The public C++ entry points are ReadKernelInput (parse the JSON request), RunKernels (run and write radial results), and ComputeSampledKernels (compute sampled 3D fields). The CLI combines these steps; library callers can use them directly.
