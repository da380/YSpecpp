Methods and validation

The numerical method, runtime controls and available tests provide evidence about a calculation; they do not turn the integration tolerance into a universal trace-error bound.

Method in brief

For each complex frequency and spherical-harmonic degree, YSpec integrates radial systems with source jumps in displacement and traction. A source is rotated to the north pole, where only orders |m| ≤ 2 contribute; the moment tensor and receiver geometry are applied afterward. The radial solution restarts at each model discontinuity and changes form between solid and fluid regions.

The integration uses a Dormand–Prince 5(4) step-controlled method. Each layer uses natural cubic splines through deck knots; gravity is integrated from the density spline. The full derivation and implementation pointers are in the README's How it works section and RadialSolver.

Model-derived latitude figure

By default, the coordinate helper solves the first-order Clairaut equation r²e″ + 6(ρ/ρ̄)r e′ + 6(ρ/ρ̄ − 1)e = 0 from a regular central solution, using the model's spline density and enclosed gravity; see Clairaut-theory background. It normalizes the surface profile with R e′(R) + 2e(R) = (5/2)Ω²R³/(GM). Geographic and geocentric latitudes are related by the first-order surface map with q = 1 − 2e(R); the inverse uses atan2 and is defined at the poles. This finite map is exactly invertible by that inverse but retains higher-order angular terms: against the strict first-order latitude series, its maximum difference is about 2.99 arcseconds for the PREM figure. It is not an exact geodetic conversion or a full nonspherical equilibrium or wave solver. Only the coordinates change; YSpec continues to propagate waves in a spherical model.

The default rate is the IAU nominal mean angular velocity of Earth (also listed by IERS) (7.292115×10−5 rad/s), and rotation_rate_rad_s overrides it. Set latitude_correction:false to treat inputs as geocentric and use the spherical identity. The model must span a regular centre to its surface; hollow models are rejected. The first-order parameter is m=Ω²R³/(GM) and the implementation rejects m≥0.1. The sampled profile uses cubic-Hermite interpolation between model knots; in a PREM diagnostic its maximum absolute profile difference from an independent dense solution was 6.85×10−10 across 415 probe radii, while surface ellipticity agreed to 4.4×10−15. This profile interpolation diagnostic is separate from the adaptive ODE tolerance. The independent reference uses YSpec's existing gravitational constant, G = 6.6723×10−11 m³ kg−1 s−2. Radial and sampled-kernel sensitivities remain derivatives of the spherical equations at fixed reference geometry; they do not include a derivative of this coordinate figure with respect to density.

A bounded same-geographic-input Bolivia run changed the epicentral distance and waveforms when switching from the former fixed Earth mapping to the model-derived default: for Z/N/E, maximum sample differences were 0.1466%, 0.0747% and 0.0649% of each component's peak (relative L2 differences 0.1054%, 0.0788% and 0.0741%). This isolates the coordinate change and says nothing about the unresolved 300-to-600-minute convergence limit. The comparison fixtures therefore supply their original geocentric coordinates with the correction disabled to preserve the documented physical setup.

Convergence checks

solver.tolerance limits local radial integration error relative to the solution. Tightening it can increase runtime, but a local step criterion is not a guarantee on the end-to-end error of every component, receiver or model. For a calculation that matters, vary the independent controls and compare the outputs of interest:

  • increase maximum spherical-harmonic degree;
  • refine the upper frequency limit and ensure the sampling Nyquist frequency is above it;
  • increase record length and reduce the time step as required by the band;
  • tighten the integration tolerance and compare traces.

Frequency-domain damping limits time wraparound for ordinary arrivals. With full gravity, ocean-surface gravity waves can outlast the record and wrap around early at and near the sea surface; a longer record or points below the surface can help. The Bolivia comparison setup reproduces the published DSpecM1D parameters, but across the three components, maximum sample differences between 300- and 600-minute runs are 1.43–2.19% of each 300-minute component peak, and relative L2 differences are 2.35–3.60% of each component’s 300-minute L2 norm, above the 1% target. It is a reproducible comparison setup, not a converged reference. The per-figure evidence and unresolved limits are recorded in the plot status and provenance record.

What the test suite checks

The existing CTest suite includes unit tests, comparisons to the original Fortran solver for selected cases, normal-mode and homogeneous-sphere checks, direct shooting, ocean/core responses, snapshot–seismogram agreement, strain reciprocity, finite-difference comparisons for radial and sampled kernels, and volume-file checks. Python tests cover the package program wrappers, seismograms, snapshots and kernels. Four end-to-end cases compare saved traces with Fortran references. Those tests describe checked cases; they do not establish accuracy for arbitrary inputs.

Use the project's standard routes: ctest --test-dir build --output-on-failure for the configured build and cmake --preset serial, cmake --build --preset serial, ctest --preset serial for the existing serial route. The current inventory is summarized in coverage and maintenance. Reference data regeneration scripts are in tests/fortran; regeneration requires a separate Fortran YSpec checkout and is not part of docs CI.

Focused troubleshooting

  • “not a recognised member”: JSON keys are case-sensitive and the parser rejects unknown keys. Compare the object with the input reference.
  • model or instrument not found: paths resolve relative to the input file. Copy required data beside it or use a path relative to that directory.
  • source-region error: all sources in one calculation must occupy one solid region. A receiver can be elsewhere (except the centre), but the radial-kernel adjoint receiver must be in the source's solid region.
  • unexpected early ocean-surface motion: inspect record length and snapshot depth for gravity-wave wraparound before interpreting the trace.
  • different runtime: runtime depends on degree, frequency, time sampling, source/receiver depths, build type and thread count. Compare like-for-like settings and record provenance.
